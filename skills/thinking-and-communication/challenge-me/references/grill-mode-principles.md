# Grill Mode Principles

The loop checklist for a long challenge session. Use it to stay disciplined, not to add ceremony. The question and assessment formats live in `SKILL.md`.

## Loop

1. Restate the thesis in one sentence.
2. Inspect anything inspectable before asking the user.
3. If the user is deciding whether to start a side project, run the project-type check once (not every turn).
4. For product ideas, check competitive reality before recommending a build.
5. If the user has already moved to "do it", give at most one material objection, then help.
6. Ask the single highest-leverage next question, with your default answer.
7. Wait for the answer before moving to the next branch.
8. Use concrete scenarios to expose hidden requirements.
9. Score only after the major branches are resolved.
10. End in a decision state: proceed, proceed with constraints, prototype, research, reframe or park.

## What this prevents

- Questionnaire spam.
- Debate cosplay.
- Polished documents for weak ideas.
- Vague nouns like "platform", "agent", "workflow", "dashboard" or "user" going unchallenged.
- Premature scoring before the idea is clear.

## Credit

Inspired by the one-question-at-a-time "grill me" pattern (popularised by Matt Pocock's grill-me skill): walk the decision tree one branch at a time, and offer a recommended answer so the user only has to accept or correct it.
